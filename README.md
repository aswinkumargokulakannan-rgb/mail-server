# Mailcow with Nginx Reverse Proxy Setup

Complete setup guide for running Mailcow in Proxmox with Nginx reverse proxy to handle all mail services through a single public IP with minimal port forwarding.

## 🚀 Quick Start

**Already have Nginx running?** (e.g., at 192.168.0.9)
→ **See [QUICK_START.md](QUICK_START.md)** for simplified setup!

**Starting from scratch?**
→ Continue reading this guide for full deployment.

## Overview

This setup allows you to run Mailcow mail server behind an Nginx reverse proxy, solving the problem of router port forwarding limitations. All mail services (SMTP, IMAP, POP3, Web UI) are proxied through a single server.

### Architecture Options

#### Option 1: Existing Nginx Server (Recommended if you have one)
```
Internet → Router → [Existing Nginx 192.168.0.9] → [Mailcow VM]
```
**Use**: `add-mailcow-to-nginx.sh` on your existing Nginx server

#### Option 2: Fresh Nginx Installation
```
Internet → Router → [New Nginx Proxy VM] → [Mailcow VM]
```
**Use**: `install-nginx-proxy.sh` to set up new Nginx proxy

## Prerequisites

### For Existing Nginx Setup (Option 1)
- **Existing Nginx server**: Already running and accessible
- **New Mailcow VM**: 6GB RAM minimum, 20GB+ disk (Ubuntu/Debian)
- Domain name with DNS control
- Router admin access (to forward mail ports)

### For Fresh Installation (Option 2)
- Proxmox server with at least 2 VMs:
  - **Nginx Proxy VM**: 1GB RAM, 10GB disk (Ubuntu/Debian)
  - **Mailcow VM**: 6GB RAM minimum, 20GB+ disk (Ubuntu/Debian)
- Domain name with DNS control
- Public IP address
- Router admin access for port forwarding

## Required Ports

You only need to forward these ports from your router to the **Nginx Proxy VM**:

| Port | Protocol | Service |
|------|----------|---------|
| 80   | TCP      | HTTP (Let's Encrypt, redirects to HTTPS) |
| 443  | TCP      | HTTPS (Web UI, SOGo) |
| 25   | TCP      | SMTP (Incoming mail) |
| 587  | TCP      | SMTP Submission (Outgoing mail) |
| 465  | TCP      | SMTPS (Outgoing mail SSL) |
| 143  | TCP      | IMAP (Email retrieval) |
| 993  | TCP      | IMAPS (Email retrieval SSL) |
| 110  | TCP      | POP3 (Email retrieval) |
| 995  | TCP      | POP3S (Email retrieval SSL) |
| 4190 | TCP      | Sieve (Email filtering) |

## Installation Steps

### Step 1: Prepare DNS Records

Before starting, configure these DNS records (replace `example.com` with your domain):

```
Type    Name                        Value               TTL
A       mail.example.com            YOUR_PUBLIC_IP      3600
MX      example.com                 mail.example.com    3600
A       autodiscover.example.com    YOUR_PUBLIC_IP      3600
A       autoconfig.example.com      YOUR_PUBLIC_IP      3600
TXT     example.com                 "v=spf1 mx ~all"    3600
```

Additional DNS records to add after setup:
- DKIM record (generated by Mailcow)
- DMARC record

### Step 2: Install Mailcow (on Mailcow VM)

1. SSH into your Mailcow VM
2. Download and run the installation script:

```bash
wget https://raw.githubusercontent.com/YOUR_REPO/mail-server/main/install-mailcow.sh
chmod +x install-mailcow.sh
sudo ./install-mailcow.sh
```

3. Follow the prompts:
   - Enter your mail server hostname (e.g., `mail.example.com`)
   - Enter your timezone (e.g., `America/New_York`)
   - Start Mailcow when prompted

4. Note the Mailcow VM's internal IP address:
```bash
ip addr show
```

### Step 3: Install Nginx Reverse Proxy (on Proxy VM)

1. SSH into your Nginx Proxy VM
2. Download and run the proxy setup script:

```bash
wget https://raw.githubusercontent.com/YOUR_REPO/mail-server/main/install-nginx-proxy.sh
chmod +x install-nginx-proxy.sh
sudo ./install-nginx-proxy.sh
```

3. Follow the prompts:
   - Enter Mailcow VM IP address (from Step 2)
   - Enter mail server hostname (e.g., `mail.example.com`)
   - Enter base domain (e.g., `example.com`)

4. The script will:
   - Install Nginx
   - Install Certbot for SSL
   - Generate Let's Encrypt SSL certificates
   - Configure HTTP/HTTPS reverse proxy
   - Configure mail protocol proxying (SMTP, IMAP, POP3)
   - Setup automatic SSL renewal

### Step 4: Configure Router Port Forwarding

Forward the required ports from your router to your **Nginx Proxy VM**:

1. Log into your router admin panel
2. Navigate to port forwarding settings
3. Forward all ports listed in the "Required Ports" section to the Nginx Proxy VM's IP address
4. Save the configuration

### Step 5: Access and Configure Mailcow

1. Access the Mailcow web interface: `https://mail.example.com`

2. Login with default credentials:
   - Username: `admin`
   - Password: `moohoo`

3. **IMPORTANT**: Change the admin password immediately!
   - Go to Settings → Admin
   - Change password

4. Configure DKIM:
   - Go to Configuration → Configuration & Details → ARC/DKIM keys
   - Generate DKIM key for your domain
   - Add the generated DKIM TXT record to your DNS

5. Add your domain:
   - Go to Configuration → Mail setup → Domains
   - Add your domain (e.g., `example.com`)

6. Create mailboxes:
   - Go to Configuration → Mail setup → Mailboxes
   - Add email accounts as needed

### Step 6: Test Your Setup

1. **Test DNS records**:
```bash
nslookup mail.example.com
dig MX example.com
```

2. **Test SMTP connection**:
```bash
telnet mail.example.com 25
```

3. **Test IMAP connection**:
```bash
openssl s_client -connect mail.example.com:993
```

4. **Send a test email**:
   - Use the Mailcow web interface to send a test email
   - Check if it arrives successfully

5. **Test email reception**:
   - Send an email from Gmail/Outlook to your new mailbox
   - Verify it arrives

6. **Check mail security**:
   - Visit https://www.mail-tester.com
   - Send an email to the provided address
   - Check your score (aim for 10/10)

## Architecture Details

### Nginx HTTP/HTTPS Proxy

- Web UI, SOGo, Autodiscover, and Autoconfig are proxied via HTTP
- Mailcow runs on internal ports 8080 (HTTP) and 8443 (HTTPS)
- Nginx handles SSL termination with Let's Encrypt certificates
- Nginx forwards requests to Mailcow's internal ports

### Nginx Stream Proxy

- Mail protocols (SMTP, IMAP, POP3) use TCP stream proxying
- Nginx forwards raw TCP connections to Mailcow
- SSL/TLS is handled by Mailcow's mail services (Postfix, Dovecot)
- No SSL termination at proxy level for mail protocols

## Configuration Files

### Mailcow Configuration

Located at: `/opt/mailcow-dockerized/mailcow.conf`

Important settings:
```bash
MAILCOW_HOSTNAME=mail.example.com
HTTP_PORT=8080
HTTPS_PORT=8443
HTTP_BIND=127.0.0.1
HTTPS_BIND=127.0.0.1
SKIP_LETS_ENCRYPT=y
```

### Nginx HTTP Configuration

Located at: `/etc/nginx/sites-available/mailcow`

Key features:
- HTTP to HTTPS redirect
- SSL certificate configuration
- Reverse proxy to Mailcow on port 8080
- Autodiscover and Autoconfig support
- WebSocket support for SOGo

### Nginx Stream Configuration

Located at: `/etc/nginx/nginx.conf` (stream block)

Proxies these mail protocols:
- SMTP: 25, 587, 465
- IMAP: 143, 993
- POP3: 110, 995
- Sieve: 4190

## Troubleshooting

### Cannot access web interface

1. Check Nginx is running:
```bash
systemctl status nginx
```

2. Check Mailcow is running:
```bash
cd /opt/mailcow-dockerized
docker-compose ps
```

3. Test connectivity from proxy to Mailcow:
```bash
curl http://MAILCOW_IP:8080
```

4. Check Nginx logs:
```bash
tail -f /var/log/nginx/mailcow-error.log
```

### Cannot send/receive emails

1. Check mail ports are open:
```bash
netstat -tulpn | grep -E ':(25|587|465|143|993|110|995)'
```

2. Test SMTP from proxy server:
```bash
telnet MAILCOW_IP 25
```

3. Check Postfix logs on Mailcow:
```bash
docker-compose logs -f postfix-mailcow
```

4. Verify DNS MX records:
```bash
dig MX example.com
```

### SSL certificate issues

1. Check certificate exists:
```bash
ls -la /etc/letsencrypt/live/mail.example.com/
```

2. Renew certificate manually:
```bash
certbot renew
systemctl reload nginx
```

3. Check certificate expiry:
```bash
certbot certificates
```

### Port forwarding issues

1. Verify router forwards to correct IP
2. Test from external network
3. Check firewall on proxy VM:
```bash
ufw status
```

If firewall is blocking, allow required ports:
```bash
ufw allow 80/tcp
ufw allow 443/tcp
ufw allow 25/tcp
ufw allow 587/tcp
ufw allow 465/tcp
ufw allow 143/tcp
ufw allow 993/tcp
ufw allow 110/tcp
ufw allow 995/tcp
ufw allow 4190/tcp
```

## Security Recommendations

1. **Firewall Configuration**:
   - Enable firewall on both VMs
   - Only allow required ports
   - Restrict SSH to specific IPs if possible

2. **Regular Updates**:
   - Keep Mailcow updated: `./update.sh`
   - Keep system updated: `apt update && apt upgrade`
   - Monitor security advisories

3. **Strong Passwords**:
   - Use strong admin password for Mailcow
   - Use strong passwords for all mailboxes
   - Enable two-factor authentication if possible

4. **Email Security**:
   - Configure SPF, DKIM, and DMARC
   - Enable spam filtering (Rspamd)
   - Enable greylisting
   - Configure fail2ban for brute force protection

5. **SSL/TLS**:
   - Use only TLSv1.2 and TLSv1.3
   - Keep certificates up to date
   - Monitor certificate expiry

6. **Monitoring**:
   - Monitor logs regularly
   - Set up alerts for failed login attempts
   - Monitor disk space and system resources
   - Use external monitoring for uptime

## Backup Strategy

### Mailcow Backup

1. **Automated backups** (recommended):
```bash
# Add to crontab
0 2 * * * cd /opt/mailcow-dockerized && ./helper-scripts/backup_and_restore.sh backup all
```

2. **Manual backup**:
```bash
cd /opt/mailcow-dockerized
./helper-scripts/backup_and_restore.sh backup all
```

Backups stored in: `/opt/mailcow-dockerized/data/assets/backup/`

3. **What to backup**:
   - Mailcow data directory: `/opt/mailcow-dockerized/`
   - SSL certificates: `/etc/letsencrypt/` (on proxy VM)
   - Nginx configuration: `/etc/nginx/` (on proxy VM)

### Restore

```bash
cd /opt/mailcow-dockerized
./helper-scripts/backup_and_restore.sh restore
```

## DNS Records Summary

After full setup, your DNS should include:

```
; A Records
mail.example.com.           IN A     YOUR_PUBLIC_IP
autodiscover.example.com.   IN A     YOUR_PUBLIC_IP
autoconfig.example.com.     IN A     YOUR_PUBLIC_IP

; MX Record
example.com.                IN MX    10 mail.example.com.

; SPF Record
example.com.                IN TXT   "v=spf1 mx ~all"

; DKIM Record (get from Mailcow)
dkim._domainkey.example.com. IN TXT  "v=DKIM1; k=rsa; p=YOUR_PUBLIC_KEY"

; DMARC Record
_dmarc.example.com.         IN TXT   "v=DMARC1; p=quarantine; rua=mailto:admin@example.com"

; Optional: Reverse DNS (PTR)
YOUR_PUBLIC_IP              IN PTR   mail.example.com.
```
